# ADR-0001: 스튜디오 경계 무결성을 애플리케이션에서 검증한다

## Status

Accepted (2026-08-06)

## Context

- 여러 도메인 객체가 스튜디오에 속하며, 서로 참조할 때도 같은 스튜디오에 속해야 해요.
- 단일 컬럼 외래 키는 참조 대상의 존재만 보장하고, 두 객체가 같은 스튜디오에 속하는지는 보장하지 못해요.
- DB에서 이 경계를 강제하려면 복합 키·복합 외래 키를 여러 관계에 추가해야 하고 JPA 매핑도 함께 복잡해져요.
- 경계 위반은 저장 전에 발견해 사용자가 이해할 수 있는 도메인 오류로 알려줄 필요가 있어요.

## Decision

스튜디오 경계를 넘는 참조는 애플리케이션 서비스에서 저장 전에 검증해요. DB의 일반 외래 키는 참조 대상의 존재를 보장하는 용도로 유지해요.

현재 단계에서는 복합 외래 키로 모든 스튜디오 경계를 강제하는 비용보다 명시적인 애플리케이션 검증이 적합하다고 판단했어요.

## Alternatives

- 복합 외래 키로 DB에서 강제 — 누락된 애플리케이션 검증도 차단할 수 있지만, 여러 테이블의 키·컬럼과 JPA 매핑이 복잡해져요.

## Consequences

- (+) 경계 위반을 저장 전에 발견하고 상황에 맞는 도메인 오류를 반환할 수 있어요.
- (+) 복합 키 도입에 따른 스키마와 JPA 매핑 복잡도를 피할 수 있어요.
- (-) 검증을 빠뜨린 저장 경로에서는 잘못된 참조가 DB에 저장될 수 있어요.
- (=) 경계가 있는 모든 쓰기 경로에 검증과 회귀 테스트가 필요해요.
- 재검토: 실제 경계 위반 데이터가 발생하거나 쓰기 경로가 늘어 검증 누락 위험을 통제하기 어려워지면 복합 외래 키 도입을 다시 판단해요.

## Compliance

- 스튜디오 범위가 포함된 조회로 참조 대상을 확인해요.
- 다른 스튜디오의 대상을 연결하려는 요청이 거부되는지 테스트해요.
