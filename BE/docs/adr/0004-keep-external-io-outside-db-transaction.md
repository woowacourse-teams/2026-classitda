# ADR-0004: 외부 I/O를 DB 트랜잭션 경계 밖에서 수행한다

## Status

Accepted (2026-08-18)

## Context

- 일부 유스케이스는 DB 작업과 Redis 또는 외부 API 호출을 함께 수행해요.
- Redis와 외부 API의 응답 시간과 장애 여부는 애플리케이션이 통제하기 어려워요.
- 트랜잭션 안에서 DB를 사용한 뒤 외부 응답을 기다리면 DB 커넥션과 락이 필요 이상으로 오래 유지될 수 있어요.
- DB 트랜잭션으로 Redis나 외부 API에서 이미 수행된 작업까지 롤백할 수는 없어요.

## Decision

Redis 또는 외부 API 호출을 포함한 전체 흐름에는 `@Transactional`을 적용하지 않아요. 외부 I/O는 DB 트랜잭션 경계 밖에서 수행해요.

원자성이 필요한 DB 쓰기만 별도의 메서드나 클래스로 분리하고, 해당 범위에만 짧게 `@Transactional`을 적용해요.

## Alternatives

- 전체 유스케이스를 하나의 DB 트랜잭션으로 처리 — DB 변경은 롤백할 수 있지만, 외부 응답을 기다리는 동안 커넥션과 락을 점유하고 외부 시스템의 작업은 함께 롤백할 수 없어요.
- 비동기로 전환 가능한 외부 작업에 Transactional Outbox 사용 — DB 변경과 Outbox 레코드 저장까지만 하나의 트랜잭션으로 처리되며, 실제 외부 작업까지 원자적으로 완료되는 것은 아니에요. 별도의 처리기·재시도·멱등성·모니터링이 필요해요.

## Consequences

- (+) 외부 응답을 기다리는 동안 DB 커넥션과 락을 점유하지 않아요.
- (+) DB 트랜잭션 범위가 실제로 원자성을 보장할 수 있는 DB 작업으로 제한돼요.
- (-) DB와 Redis 또는 외부 API 사이의 원자성을 보장할 수 없어요.
- (-) 한쪽 작업만 성공하는 부분 실패가 발생할 수 있어요.
- (=) 외부 호출의 순서, 멱등성, 재시도 또는 보상 방법을 유스케이스별로 결정해야 해요.
- 재검토: 부분 실패가 실제 정합성 문제로 이어지거나 더 강한 일관성이 필요해지면 작업 간 상태를 조정하는 방법을 다시 결정해요.

## Compliance

- 외부 I/O를 포함하는 오케스트레이션 메서드나 클래스 전체를 DB 트랜잭션으로 묶지 않아요.
- 함께 성공하거나 실패해야 하는 DB 쓰기만 명시적인 트랜잭션 경계로 분리해요.
- 부분 실패 시 각 단계의 완료 상태와 후속 처리를 테스트해요.
