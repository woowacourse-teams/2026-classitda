## 다른 문서와의 관계

| 문서 | 성격 |
| --- | --- |
| [`../decisions/backend-tech-stack.md`](../decisions/backend-tech-stack.md) | 기술 스택 선정 근거 (상시 참조) |
| [`../decisions/backend-code-convention.md`](../decisions/backend-code-convention.md) | 코드 컨벤션 규약 (상시 참조) |
| `docs/adr/**` | 시점별 의사결정 기록 |

**컨벤션 문서와 ADR이 충돌하면 컨벤션 문서가 우선해요.** ADR은 결정 당시의 맥락과 근거를 담고, 컨벤션 문서는 현재 지켜야 할 규칙을 담아요. ADR을 채택한 뒤 규칙이 컨벤션 문서에도 들어가야 하는 성격이면 컨벤션 문서를 함께 갱신해요.

## 이 문서로 자기 하네스를 구성하려면

에이전트 하네스(`.claude/`, `CLAUDE.md`)는 `.gitignore`에 걸려 있어서 **저장소로 공유되지 않아요.** 각자 구성하되, 아래 ADR의 `## 규칙` 절이 하네스에 그대로 옮겨야 할 내용이에요.

권장 매핑이에요.

| ADR | 옮겨 넣을 곳 |
| --- | --- |
| 0001 | 파이프라인·오케스트레이션 스킬 (없으면 `CLAUDE.md`의 작업 절차) |
| 0002, 0003 | 설계 스킬 — 저장 전 검증 위치를 설계 문서에 적게 하는 항목 |
| 0004, 0005, 0006 | 컨벤션·구현 스킬 |
| 0007 | 테스트 스킬 |
| 0008 | 리뷰 스킬 |

각 ADR의 `## 규칙`은 **판정 가능한 문장**으로 써 뒀어요. "적절히", "가능하면" 같은 표현이 없어야 리뷰 단계에서 위반 여부를 다투지 않아요. 하네스에 옮길 때도 그 성질을 유지해 주세요.

## 새 ADR을 쓸 때

- 파일명은 `{4자리 번호}-{영문-kebab}.md`예요.
- 형식은 기존 문서와 맞춰요 — `후보 / 선택 / 🤔 선택 근거 / 규칙 / 감수하는 점`.
- **결정을 되돌릴 때 기존 ADR을 지우지 않아요.** 상태를 `대체됨 (→ ADR-XXXX)`으로 바꾸고 새 문서를 추가해요. 지우면 "왜 그때 그렇게 했는지"가 사라져서 같은 논의를 반복하게 돼요.
