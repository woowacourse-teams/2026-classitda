# ADR-0004. 와일드카드 임포트를 쓰지 않아요

- 상태: 채택 (2026-08-06)
- 후보: IDE 기본 임계값(클래스 5개·정적 3개부터 자동으로 접기) 허용, 전면 금지
- 선택: 전면 금지 + `.editorconfig`로 고정
- 관련: [ADR-0008](0008-review-severity.md)

---

## 🤔 선택 근거

### 타입이 어디서 왔는지 파일만 보고 알 수 있어야 해요

`import jakarta.persistence.*;`가 있으면 `Table`이 JPA의 것인지 다른 패키지의 것인지 파일 안에서 확인할 수 없어요. IDE 없이 보는 상황 — 깃허브 diff, 코드 리뷰, 터미널 — 에서 매번 추측하게 돼요.

### 동명 클래스 충돌이 조용히 생겨요

서로 다른 패키지에 같은 이름의 클래스가 있을 때 와일드카드를 쓰면 충돌 지점이 드러나지 않아요. 나중에 어느 한쪽 패키지에 같은 이름이 추가되기만 해도 컴파일이 깨지거나, 더 나쁘게는 의도하지 않은 타입이 선택돼요.

우리는 도메인마다 `Status` 계열 enum이 여러 개(`ClassSessionStatus`, `ReservationStatus`, `WaitingStatus`, `MembershipStatus`, `MemberPassStatus`)라 이 위험이 실제로 있어요.

### 임계값 방식은 diff를 흔들어요

IDE 기본값은 "임포트가 5개를 넘으면 자동으로 접기"예요. 이러면 클래스 하나를 추가·삭제할 때 임포트 블록 전체가 한 줄로 접히거나 다시 펼쳐져요. 로직 한 줄 바꾼 커밋에 임포트 변경이 섞여서 리뷰에서 볼 것이 늘어나요.

### 실제로 IDE 자동 정리로 들어왔어요

이 규칙은 처음부터 있던 게 아니라, 작업 중 IDE 자동 정리로 와일드카드가 유입된 걸 발견하고 팀이 금지하기로 한 거예요. 사람이 매번 눈으로 잡을 수 있는 종류가 아니라서 설정으로 고정했어요.

---

## 규칙

- **와일드카드 임포트를 쓰지 않아요.** 클래스 개수와 무관하게 항상 명시적으로 나열해요. 정적 임포트도 같아요.
- **임포트 순서는 정적 임포트 먼저, 나머지는 하나의 알파벳 블록이에요.** 패키지별로 그룹을 나누고 빈 줄로 구분하지 않아요.
- 설정은 `BE/.editorconfig`에 있어요. IntelliJ가 이 파일을 읽으니 별도 설정 공유가 필요 없어요.

```editorconfig
[*.java]
ij_java_class_count_to_use_import_on_demand = 999
ij_java_names_count_to_use_static_import_on_demand = 999
ij_java_packages_to_use_import_on_demand =
ij_java_imports_layout = $*, |, *
```

- **리뷰에서 확인해요.** 설정이 있어도 다른 편집기나 설정을 덮어쓴 환경에서 들어올 수 있어요.

---

## 감수하는 점

- **임포트 줄이 길어져요.** JPA 엔티티는 임포트만 20줄이 넘어요. IDE에서 접어서 보면 되는 문제라 받아들이기로 했어요.
- **`.editorconfig`를 읽지 않는 편집기에서는 강제되지 않아요.** 그래서 리뷰 확인 항목으로도 둬요.
