# ADR-0008: RDS를 저장 시 암호화 없이 운영한다

## Status

Accepted (2026-08-19)

## Context

- 우아한테크코스 AWS 계정의 IAM 사용자에게 KMS 권한이 없다. 콘솔에서는 `kms:ListAliases` 거부로 키 목록이 뜨지 않고, CLI에서 기본 키를 지정해도 `The specified KMS key [null] ... isn't accessible`로 생성이 실패했다.
- 팀은 리소스를 삭제할 권한이 없다. 잘못 만든 리소스는 별도 요청으로만 정리할 수 있다.
- `member` 테이블에 이름과 휴대전화번호가 저장된다. 강사가 미가입자를 등록하는 흐름이 있어 본인 동의 없이 수집되는 정보도 포함된다.
- RDS 저장 시 암호화는 생성 시점에만 지정할 수 있다.

## Decision

저장 시 암호화 없이 RDS를 생성하고, 대신 다른 계층에서 보완한다. JDBC URL에 `sslMode=REQUIRED`를 지정해 전송 구간 암호화를 강제하고, 퍼블릭 액세스를 차단하며, 애플리케이션 전용 계정에 DDL 권한을 주지 않는다. KMS 권한 확보를 기다리면 배포 일정 전체가 멈추고, 나중에 켜는 경로도 남아 있다고 판단했다.

## Alternatives

- **KMS 권한을 요청하고 대기** — 답변까지 인프라 구축이 멈춘다.
- **암호화 없이 만든 뒤 나중에 스냅샷 복원으로 전환** — 가능한 경로이지만 팀에 삭제 권한이 없어 옛 인스턴스가 계속 과금된다. 예산 여유가 크지 않아 그 자체가 부담이다.
- **`admin` 계정을 애플리케이션에 그대로 사용** — 계정 하나가 유출되면 DB 전체 권한이 함께 넘어가므로 채택하지 않고, 전용 계정을 만들었다.

## Consequences

- (+) KMS 권한을 기다리지 않고 배포를 진행할 수 있었다.
- (+) 전송 구간은 `sslMode=REQUIRED`로 강제된다. 드라이버 기본값 `PREFERRED`는 TLS에 실패하면 평문으로 붙으므로 명시적으로 막았다.
- (-) **디스크·스냅샷 수준의 접근으로부터 데이터가 보호되지 않는다.** 스냅샷도 암호화되지 않으므로 다른 계정과 공유해서는 안 된다.
- (-) **되돌리는 비용이 크다.** 스냅샷 → 암호화 복사 → 복원이 필요하고, 그동안 인스턴스 두 개가 동시에 과금되며 데이터 이전 중 다운타임이 생긴다.
- (=) `sslMode=REQUIRED`는 서버 인증서를 검증하지 않는다. 중간자 공격까지 막으려면 RDS CA 번들을 트러스트스토어에 넣고 `VERIFY_CA`로 올려야 한다.
- (=) 개인정보 처리방침의 안전성 확보 조치를 기술할 때 이 상태를 반영해야 한다.
- 재검토: KMS 권한이 확보될 때. 실제 사용자 데이터가 쌓이기 전. 개인정보 관련 검토에서 요구될 때.

## Compliance

- 애플리케이션 계정 권한을 확인한다. `SHOW GRANTS FOR 'classitda'@'%'`에 `CREATE`·`DROP`·`ALTER`가 없어야 한다.
- RDS 인스턴스의 퍼블릭 액세스가 비활성인지 확인한다.
