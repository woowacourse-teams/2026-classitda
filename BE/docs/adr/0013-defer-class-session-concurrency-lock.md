# ADR-0013: 수업 시간 충돌에 대한 비관적 락 적용을 유예한다

## Status

Accepted (2026-08-16)

## Context

- 수업을 저장하기 전에 담당 강사의 기존 수업과 시간이 겹치는지 애플리케이션에서 확인해요.
- 서로 다른 시작 시각의 겹치는 수업 생성 요청이 동시에 들어오면 두 요청이 모두 검증을 통과할 수 있어요.
- 수업 생성과 관리는 관리자 역할을 가진 강사가 담당해요.
- 여러 관리자가 동일한 담당 강사의 일정에 시간이 겹치는 수업을 동시에 생성하거나 변경할 가능성은 낮다고 판단했어요.
- 비관적 락으로 충돌을 막으려면 생성·수정·취소·관리자 지정 등 모든 일정 변경 경로가 같은 대상에 같은 순서로 락을 적용해야 해요.

## Decision

현재 수업 생성에는 비관적 락을 적용하거나 트랜잭션 격리 수준을 별도로 변경하지 않아요.

애플리케이션의 시간 겹침 검증만 사용하고, 비관적 락 적용은 관련 일정 변경 경로가 갖춰질 때까지 유예해요.

## Alternatives

- 담당 강사 소속에 비관적 락 적용 — 같은 강사의 일정 변경을 한 번에 하나씩 처리할 수 있지만, 모든 일정 변경 경로가 동일한 대상을 먼저 락으로 조회해야 해요.

## Consequences

- (+) 동시 요청이 아니라면 애플리케이션의 시간 겹침 검증으로 충돌하는 수업의 저장을 막을 수 있어요.
- (+) 같은 강사와 같은 시작 시각의 활성 수업 중복은 DB 유니크 제약이 차단해요.
- (+) 현재 단계에서 락 대기와 트랜잭션 복잡도를 추가하지 않아도 돼요.
- (-) 시작 시각은 다르지만 시간이 겹치는 요청이 동시에 검증되면, 시간 구간 중복을 막는 DB 제약이 없어 두 수업이 모두 저장될 수 있어요.
- 재검토: 여러 관리자가 같은 강사의 수업을 동시에 다루는 운영 흐름이 생기거나 실제 시간 충돌이 발생하면, 비관적 락을 어디에 어떤 순서로 적용할지 다시 결정하고 동시성 테스트로 검증해요.
